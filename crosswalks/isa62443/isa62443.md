## 1. Scope of ISA/IEC 62443

ISA/IEC 62443 is a series for the security of industrial automation and control systems (IACS) across asset owners, service providers and product suppliers. Parts used here:

| Part | Subject | Principal role |
|---|---|---|
| 62443-2-1 | Security program requirements for IACS asset owners | Asset owner |
| 62443-2-4 | Security program requirements for IACS service providers (integration and maintenance) | Service provider |
| 62443-3-2 | Security risk assessment for system design: zones, conduits and target security levels | Asset owner, integrator |
| 62443-3-3 | System security requirements and security levels | Integrator, asset owner |
| 62443-4-1 | Secure product development lifecycle requirements | Product supplier |
| 62443-4-2 | Technical security requirements for IACS components | Product supplier |

System and component requirements are organised under seven foundational requirements: FR1 identification and authentication control, FR2 use control, FR3 system integrity, FR4 data confidentiality, FR5 restricted data flow, FR6 timely response to events, FR7 resource availability. Security levels (SL 1–4) express resistance to increasingly capable threats; a target level (SL-T) is set per zone, compared with the capability of components (SL-C) and the achieved level (SL-A). Certification of products, processes and systems against several parts is available through recognised conformity-assessment schemes.

## 2. Where it overlaps with AIDCF

Data centre BMS, EPMS, CDU and cooling-plant controllers, generator and switchgear controls and fire-system interfaces are IACS. ISA/IEC 62443 is therefore the primary external reference for the OT portion of the SEC domain and for CG-07 (critical control-system integrity) and CG-15 (integrated digital authority).

- **SEC-01, SEC-03** (identity, use control, zoning and conduits) are HIGH-confidence PARTIAL mappings to 3-2 and 3-3 FR1, FR2, FR5.
- **SEC-02** control-plane protection: BMS and EPMS security is covered strongly; cluster manager, fabric controller and storage controller security is not IACS.
- **DEP-05** boundary and cross-boundary enforcement: zones and conduits (HIGH).
- **SUP-04, SUP-06**: secure update management (4-1, 4-2) and service-provider remote access (2-4).
- **RES-02, RES-04**: zones as cyber containment boundaries; FR7 backup, recovery and reconstitution.
- **GOV-01 to GOV-03**: asset-owner security program (2-1).

## 3. Where AIDCF goes beyond ISA/IEC 62443

- 62443 addresses security of control systems; it does not address whether the controlled plant (power, cooling) delivers its function, or the safety of hazardous testing (POW, THM, CG-04 to CG-06).
- AI compute, storage and network domains, and their control planes outside IACS, are not addressed.
- Capability outcomes, dependency and concentration analysis, environmental performance and evidence-based decisions are AIDCF-specific.
- SEC-06 (AI agent or automation authority over infrastructure) is addressed only by generic use control (FR2).

## 4. Using ISA/IEC 62443 outputs as AIDCF evidence

| Output | AIDCF evidence class | Useful for | Limits |
|---|---|---|---|
| Zone and conduit model with SL-T per zone (3-2) | E1/E7 | DEP-05, SEC-03, RES-02, DEP-01 | Must be reconciled to as-built network and controller configuration |
| SL-A assessment or system certification against 3-3 | E4/E5 | SEC-01, SEC-02 (OT), SEC-05; CG-07, CG-15 | Scope of system under consideration; point in time |
| Product certification against 4-1 / 4-2 | E5 | SUP-04, CMP-04 context, SEC-02 component capability | SL-C of a component is not SL-A of the system |
| Service-provider assessment against 2-4 | E5 | SUP-01, SUP-06, DEP-03 | Provider capability; not evidence of current session control |
| Asset-owner program evidence (2-1) | E1/E3 | GOV-01 to GOV-03, SEC-04 | Program existence; effectiveness requires operational evidence |

## 5. Gaps and cautions

- Several parts have had recent revisions (for example 2-1); confirm editions and terminology in use.
- FR4 data confidentiality has no strong AIDCF counterpart at family level and is not mapped separately.
- Patch management for IACS is addressed in the technical report IEC TR 62443-2-3, cited in SEC-04 notes for context.
