## 3. Disclosed deviations from revision 4

1. **Separate comparative sheet.** Rev 4 §8 put the new record types and columns into `coding-sheet.csv`. They are in a separate `comparative-sheet.csv` instead. Reasons: baseline coders work in a file that is locked independently of the AIDCF codings (§4 blinding), and the v1.0 coding sheet, its dictionary and every v1.0 check stay byte-for-byte unchanged. The AIDCF side of every pair is still read from `coding-sheet.csv` with v1.0 semantics.
2. **AIDCF EOD in its own record type.** Rev 4 §8 put AIDCF EOD columns on CONTROL rows. They are AIDCF_EOD rows in the comparative sheet, one per sampled factor, for the same reason.
3. **Knowability and coding phase on FACTOR rows.** These are copied onto FACTOR rows so the EOD frame can be frozen before any judgement exists. They must equal the RECONCILED values in `coding-sheet.csv` (checked).
4. **NOT_ADDRESSED on the baseline side** leaves `baseline_criteria` empty and must explain in `notes` what was searched. Rev 4 said every determinate value cites a clause; there is no clause to cite for "no criterion covers it".
5. **One added output line in v1.0 `--check`:** "comparative (v1.1 section 10A): N comparative-sheet rows checked". Every other v1.0 output is identical (§5).
