**AIDCF**

**AI Data Centre Facilities Assurance Framework**

**ASSURANCE PROGRAM FRAMEWORK**

**Version 1.0**

**  
A non-certification program standard for commissioning, governing, delivering, reviewing and sustaining AIDCF assurance**

Artifact ID: AIDCF-APF-001  
Status: Draft for controlled review  
Author: Siva Sethumadhavan  
Depends on: AIDCF-006 through AIDCF-010

**  
AIDCF defines the method. Users and assurance providers apply it. Accountable organisations own risks and decisions. This framework issues no certificate.**

# Document control

| **Field**         | **Value**                                                                                                                  |
|-------------------|----------------------------------------------------------------------------------------------------------------------------|
| Purpose           | Define repeatable AIDCF assurance programs without establishing AIDCF as a certification or accreditation body.            |
| Users             | Organisations, customers, assurance providers, internal audit, investors and regulators using AIDCF for bounded decisions. |
| Inputs            | Controls, evidence, workpapers, gates, scores, findings, scenarios and decisions.                                          |
| Outputs           | Charter, plan, assessment package, bounded statement, action plan, reassessment and continuing-assurance records.          |
| Non-certification | No AIDCF certificate, certification mark, accredited status or universal claim is created.                                 |
| Safety            | No program authorises hazardous testing or replaces licensed professional judgment.                                        |

# Executive thesis

**AIDCF-011 converts the AIDCF method into a usable assurance program while preserving the separation between framework ownership, assessment delivery, evidence review, management accountability and any separately regulated certification activity.**

# Part I - Authority and boundaries

**AIDCF-011 standardises programs, not certification.**

| **Element**            | **Program rule**                                                                                                 |
|------------------------|------------------------------------------------------------------------------------------------------------------|
| Framework owner        | Maintains methodology, schemas and change control.                                                               |
| Program sponsor        | Defines and authorises the decision need.                                                                        |
| Assessed organisation  | Owns capability, evidence access, risks and actions.                                                             |
| Assurance provider     | Performs work under its own professional and contractual authority.                                              |
| Decision authority     | Issues or withholds a bounded conclusion.                                                                        |
| Permitted wording      | Assessed using AIDCF; AIDCF-aligned assessment; provider-issued AIDCF-aligned assurance statement.               |
| Prohibited wording     | AIDCF Certified; AIDCF Accredited; universal safe/secure/resilient claim.                                        |
| Separate certification | Any certification scheme is outside this framework and remains the responsibility of a separately governed body. |

# Part II - Program principles

**Programs retain AIDCF constitutional invariants.**

| **Element**         | **Program rule**                                                                 |
|---------------------|----------------------------------------------------------------------------------|
| Capability first    | Defined Capability Instance and Service Outcomes.                                |
| Evidence gated      | Every material claim has evidence or explicit UNKNOWN.                           |
| UNKNOWN visible     | Missing, stale, inaccessible and conflicting evidence remains non-favourable.    |
| Gate dominance      | Critical gates cannot be averaged away.                                          |
| State distinction   | Design, implementation, operation, effectiveness and resilience remain distinct. |
| Boundary visibility | External and excluded dependencies remain visible.                               |
| Safety              | Collection and testing are authorised and proportionate.                         |
| Competence          | Collective technical and assurance competence.                                   |
| Bounded conclusion  | Scope, state, time, evidence and limitations.                                    |
| Reassessment        | Material change can suspend prior reliance.                                      |

# Part III - Program models

**AIDCF supports multiple assurance relationships.**

| **Element**             | **Program rule**                                                                                    |
|-------------------------|-----------------------------------------------------------------------------------------------------|
| First-party             | Organisation self-assessment for readiness and improvement.                                         |
| Co-sourced              | Management and provider share work with explicit responsibility split.                              |
| Second-party            | Customer, investor or contracting party assesses a provider for a decision.                         |
| Independent third-party | Provider performs work and issues its own bounded statement.                                        |
| Regulatory support      | Structures evidence and analysis; does not determine legal compliance unless separately authorised. |
| Diligence               | Bounded review for transaction, finance, capacity or outsourcing.                                   |
| Internal audit          | May use AIDCF under its existing charter and standards.                                             |
| Continuing assurance    | Claim-specific evidence refresh and event-driven reassessment, not universal continuous assurance.  |

# Part IV - Assurance levels

**Levels describe depth, not certification grades.**

| **Element**                      | **Program rule**                                                 |
|----------------------------------|------------------------------------------------------------------|
| AL0 Discovery                    | Inventory and decision discovery; no conclusion.                 |
| AL1 Readiness                    | Scope, ownership, applicability and evidence readiness.          |
| AL2 Design                       | Requirements, architecture and safeguard design.                 |
| AL3 Implementation               | Reconciliation to implemented/as-built state.                    |
| AL4 Operational                  | Representative operation, monitoring, maintenance and incidents. |
| AL5 Effectiveness and resilience | Safeguard effectiveness, failure containment and recovery.       |
| AL6 Continuing                   | Refresh approved claims, evidence, gates and triggers.           |

# Part V - Assessment types

**Select the assessment type from the decision question and lifecycle event.**

| **Element**        | **Program rule**                                         |
|--------------------|----------------------------------------------------------|
| Baseline           | Initial capability-wide understanding.                   |
| Readiness          | Preparation for deployment or deeper assurance.          |
| Design             | Pre-build/architecture decision support.                 |
| Implementation     | As-built, commissioning or handover.                     |
| Operational        | Current operating effectiveness over a declared period.  |
| Resilience         | Failure, degraded state, containment and recovery.       |
| Major change       | Delta assessment after material change.                  |
| Incident triggered | Impact on prior claims and residual state.               |
| Periodic           | Planned reassessment of defined claims/gates.            |
| Continuous         | Evidence and trigger monitoring for approved assertions. |

# Part VIII - Independence

**Safeguards depend on intended reliance and provider model.**

| **Element**             | **Program rule**                                                 |
|-------------------------|------------------------------------------------------------------|
| Self-assessment         | Management review plus independent challenge for material gates. |
| Co-sourced              | Separate preparation, testing, evaluation and review.            |
| Second-party            | Disclose commissioner, purpose and access constraints.           |
| Independent provider    | Apply provider conflict, quality and liability rules.            |
| Prior advisory work     | Address self-review threat or restrict scope.                    |
| Outcome-contingent fees | Prohibited for assurance conclusions.                            |
| Management decisions    | Assessors do not accept risk or operate controls for management. |
| Specialist reliance     | Record competence, scope and responsibility.                     |

# Part XIV - Prohibited claims

**Prevent understatement of limits and overstatement of AIDCF authority.**

| **Element**                       | **Program rule**                                                         |
|-----------------------------------|--------------------------------------------------------------------------|
| AIDCF Certified                   | Prohibited.                                                              |
| AIDCF Accredited                  | Prohibited.                                                              |
| Compliant with all laws           | Prohibited unless separately authorised and evidenced.                   |
| Safe/secure/resilient universally | Prohibited guarantee.                                                    |
| Continuous assurance universally  | Prohibited unless specific monitored claims and blind spots are defined. |
| Pass based on score               | Prohibited when gates or UNKNOWN control.                                |
| Engineering approval              | AIDCF does not replace it.                                               |
| Framework-owner endorsement       | Not implied by use.                                                      |
| Public ranking                    | Requires separate approved cohort method.                                |
| Transfer of assurance             | Requires applicability across capability, boundary, state and time.      |

# Part XVI - Validity and reassessment

**No conclusion remains valid indefinitely by default.**

| **Element**     | **Program rule**                                                 |
|-----------------|------------------------------------------------------------------|
| Validity        | Point-in-time/period, conditions and evidence basis.             |
| Evidence expiry | Mandatory evidence expiry triggers review.                       |
| Material change | Architecture, capacity, configuration, supplier or ownership.    |
| Incident        | May suspend affected claims.                                     |
| Gate change     | FAIL/critical UNKNOWN triggers review.                           |
| Closure         | Requires evidence and reassessment.                              |
| Periodic review | Set by risk, freshness and reliance.                             |
| Supersession    | Preserve prior history.                                          |
| Withdrawal      | Issuer removes conclusion when reliance is no longer defensible. |

# Part XVII - Continuing assurance

**Continuing assurance is claim-specific monitoring plus human decision.**

| **Element**      | **Program rule**                                                    |
|------------------|---------------------------------------------------------------------|
| Baseline         | Initial defensible assessment.                                      |
| Source register  | Authoritative sources, owners and health.                           |
| Monitored claims | Explicit propositions, states and dependencies.                     |
| Refresh          | Evidence validation cadence.                                        |
| Triggers         | Change, incident, threshold, missing data, conflict and gate event. |
| Blind spots      | Source outage and uncovered states visible.                         |
| Human review     | Automation proposes; authority approves material status.            |
| Decision state   | Maintain, condition, suspend, withdraw or reassess.                 |
| Snapshot         | Immutable evidence, rules and lineage.                              |

# Part XVIII - Quality and challenge

**Quality protects conclusions from unsupported or commercial pressure.**

| **Element**        | **Program rule**                                      |
|--------------------|-------------------------------------------------------|
| Quality plan       | Review points and technical approvals.                |
| Hot review         | Before material conclusion.                           |
| Cold review        | Post-issuance sample.                                 |
| Consultation       | Resolve specialist disagreement.                      |
| Evidence challenge | Assertion-to-evidence trace and contrary evidence.    |
| Appeal             | Challenge facts/method, not negotiate outcome.        |
| Complaint          | Conduct, confidentiality and process concerns.        |
| Correction         | Material error triggers corrected/superseding report. |
| Conflict register  | Commercial, management and reviewer conflicts.        |

# Part XIX - Data and graph

**Assurance does not justify overcollection or exposure of infrastructure paths.**

| **Element**        | **Program rule**                                               |
|--------------------|----------------------------------------------------------------|
| Minimisation       | Collect only for precise assertions.                           |
| Authorisation      | Source-owner approval.                                         |
| Classification     | Protect architecture, credentials, controls and dependencies.  |
| Segregation        | Separate client, provider and public packages.                 |
| Redaction          | Preserve limitations when details withheld.                    |
| Retention/deletion | Preserve obligations and lineage.                              |
| Graph security     | Restrict sensitive paths and exports.                          |
| AI use             | AI-derived material is candidate, lineage-linked and reviewed. |
| Native conclusions | AIDCF and AITG decisions remain separate.                      |

## Final doctrine

**AIDCF-011 enables disciplined assurance programs without presenting AIDCF as a certifying or accrediting body. The issuer remains responsible for competence, independence, professional obligations and the bounded statement issued. The assessed organisation remains responsible for the capability, risks, controls, actions and decisions.**
